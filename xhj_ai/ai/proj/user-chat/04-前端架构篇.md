# 前后端分离架构实践

> 本文是 user-chat 全栈项目学习笔记系列第 4 篇，讲解模块化思想与前后端分离架构。

---

## 一、AI 全栈开发

### 1.1 什么是全栈？

```
┌─────────────────────────────────┐
│          AI 全栈开发             │
├─────────┬───────────┬───────────┤
│  前端   │   后端    │    AI     │
│ fe/     │ backend/  │   ...     │
└─────────┴───────────┴───────────┘
```

JS 可以做前端、后端、AI，是一门全栈语言。

### 1.2 项目结构

```
user-chat/
├── fe/              # 前端目录
│   ├── index.html   # 页面结构
│   └── common.js    # 业务逻辑
├── backend/         # 后端目录
│   ├── db.json      # 数据存储
│   └── package.json # 项目配置
└── readme.md        # 项目说明
```

## 二、模块化思想

### 2.1 为什么需要模块化？

> 代码、功能都放在一个文件，少数文件或目录 → 不好维护，不好扩展，不好优化

**模块化的好处：**
- 每个文件夹有它的职责划分
- 每个文件只做一件事（一个文件一个类）
- 便于维护、扩展、优化

### 2.2 职责划分

```
┌─────────────────────────────────────┐
│            项目根目录                │
├─────────────┬───────────────────────┤
│   fe/       │      backend/         │
│  前端职责    │     后端职责          │
├─────────────┼───────────────────────┤
│ index.html  │  db.json              │
│ 页面结构     │  数据存储             │
├─────────────┼───────────────────────┤
│ common.js   │  package.json         │
│ 业务逻辑     │  项目配置             │
└─────────────┴───────────────────────┘
```

### 2.3 前端三件套职责

| 技术 | 职责 | 引入方式 |
|---|---|---|
| **HTML** | 结构（标签） | .html 文件 |
| **CSS** | 样式 | `<link>` 头部引入 |
| **JS** | 行为 | `<script>` 尾部引入 |

```html
<!-- HTML 结构 -->
<head>
    <!-- CSS 样式：头部引入 -->
    <link href="bootstrap.min.css" rel="stylesheet">
</head>
<body>
    <!-- HTML 内容 -->
    <!-- JS 行为：尾部引入 -->
    <script src="./common.js"></script>
</body>
```

## 三、前后端数据流

### 3.1 完整数据流

```
┌──────────┐    fetch请求     ┌──────────────┐
│  前端    │ ──────────────→ │   后端       │
│ (浏览器) │                 │ (json-server)│
│          │ ← JSON 数据 ─── │              │
└──────────┘                 └──────────────┘
     ↓
┌──────────┐
│ 渲染DOM  │
│ 挂载点   │
└──────────┘
```

### 3.2 数据流详解

```
1. 前端发起请求
   fetch('http://localhost:3000/users')
        ↓
2. 后端返回 JSON 数据
   [{ id:1, name:'xi haojun', ... }, ...]
        ↓
3. 前端解析数据
   .then(data => data.json())
        ↓
4. 找到挂载点
   document.querySelector('.table tbody')
        ↓
5. 渲染到页面
   oBody.innerHTML += `<tr>...</tr>`
```

### 3.3 前后端通信协议

| 层面 | 前端 | 后端 |
|---|---|---|
| 语言 | JavaScript | JavaScript (Node.js) |
| 运行环境 | 浏览器 | 服务器 |
| 通信方式 | fetch 请求 | HTTP API |
| 数据格式 | JSON | JSON |

## 四、大厂关注的底层能力

### 4.1 核心能力清单

```
大厂特别注重底层
├── HTML 语义化标签
├── JS DOM 编程
├── 模块化 动态插入 HTML
└── 理解 document 对象
    ├── document 是树状结构
    ├── document.documentElement 是根节点
    ├── document.body 是我们看到的页面
    └── document.querySelector 进行 travel 查找树
        ├── 查看节点
        ├── 知道孩子节点
        ├── 知道兄弟节点
        └── 挂载节点
```

### 4.2 为什么注重底层？

| 能力 | 体现 |
|---|---|
| 语义化标签 | 不是 div 一把梭，代码可读性 |
| DOM 编程 | 理解浏览器渲染原理 |
| 模块化 | 工程化思维，可维护性 |
| document 对象 | 底层 API 理解，框架原理基础 |

## 五、项目设计原则

### 5.1 单一职责原则

```
每个文件只做一件事：
├── index.html  → 只负责结构
├── common.js   → 只负责逻辑
├── db.json     → 只负责数据
└── package.json → 只负责配置
```

### 5.2 关注点分离

```
前端关注：              后端关注：
├── 用户界面            ├── 数据存储
├── 交互体验            ├── 业务逻辑
├── 数据展示            ├── API 设计
└── DOM 操作            └── 数据安全
```
