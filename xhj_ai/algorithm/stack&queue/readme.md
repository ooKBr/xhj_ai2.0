## 栈和队列特性
看成操作受限的数组，特殊的数组
栈只能在栈顶操作，数组的尾部操作。LIFO 后进先出 体现在尾端进行操作。
队列只能在队尾入队，在队首出队。 FIFO 先进先出 体现在队首进行操作。
也可以用链表来表达 

## 灵活增删的数组
- 增加元素的方法
  - push() 向数组尾部添加一个或多个元素，返回新的数组长度。 
  - unshift() 向数组头部添加一个或多个元素，返回新的数组长度。
  - splice() 既可以做删除也可以做插入元素，插入位置任意
    MDN文档
    splice(start_index, del_count, ...added)  
    // start_index 插入位置 del_count 删除元素数量 added 是插入的元素。
    // 如果del_count 为0，则不删除元素，只插入元素，added 数量随便，如果为0，则不插入
push 添加一般来说更高效 数组扩容的问题 链表没有这个问题
unshift 实际上是把每个元素都向后移动，再在头部插入元素。
- 数组的增删 都不是纯函数，操作后的结果可以找原数组拿

## 链表
- 数组增加元素，arr.length >= capacity扩容和初始化 有内存申请分配的开销，其余时刻是没有的
- 链表 每次都申请 开销平均
数据的规模
  小规模 数组
  大规模 链表
数组的优势 遍历，索引取元素，缺点是增删，易懂位置和申请空间
链表的优势 增删（找到前驱节点） 缺点是找到相应节点

链表和数组相似的，他们都是**有序**的列表（list），都是线性结构（有且只有一个前驱、有且只有一个后继）。
  数组 array 索引
  链表 linked list head-> node... -> tail

链表中，数据单位节点，指针
节点和节点的分布是不连续的，是离散的
// js 用对象字面量
{
    val:1,
    next: {
        val:2,
        next: 
    }
}

为什么要有head 节点？
访问链表中的任何一个元素，从起始节点开始（val 空），逐个访问next，一直访问到目标节点为止，tail 节点 next 为空

## 删除
前驱节点

假设数组的长度是n,因增加/删除操作导致需要移动的元素数量，随着数组长度n的增大而增大，呈现一个线性关系。
增加，删除操作对应的复杂度是O（n）
- js 数组特性

JS 数组未必是真正的数组，如果每一项类型一致，存数组，那么就是连续内存，
如果类型不同，那么就是一段非连续内存，JS 数组不再具备数组的特征，底层使用哈希分配内存空间。

链表有着高效的增删操作O（n） 固定的，明确到插入/删除的目标位置，接着只需要改变目标节点及其前驱/后继节点指针的指向（O（1））。
麻烦的访问操作O(n)，就不如数组能直接访问到（O（1））
