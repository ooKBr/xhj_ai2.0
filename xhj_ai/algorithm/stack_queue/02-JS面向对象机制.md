# JS 不需要 class 也能面向对象？

> 从一道算法题出发，理解 JavaScript 独特的面向对象机制。

## 前言

写 LeetCode 算法题时，题目经常要求你实现一个类：

```
实现 MyQueue 类：
void push(int x)
int pop()
int peek()
boolean empty()
```

Java、C++ 里必须先写 `class`，但 JS 不需要。**JS 没有类，只有对象。** 这是怎么回事？

---

## 一、函数是一等对象

JS 中，函数本身就是对象，可以：
- 赋值给变量
- 作为参数传递
- **当作构造函数来 new**

```javascript
// 这就是一个普通函数
function MyQueue() {
    this.stack1 = [];
    this.stack2 = [];
}
```

---

## 二、普通函数 vs 构造函数：this 的区别

同一个函数，调用方式不同，`this` 指向完全不同：

```javascript
function Person(name) {
    this.name = name;
    console.log(this);
}

// ① 普通函数调用 → this 指向全局对象
Person('xhj');
// this → window（浏览器）/ global（Node）

// ② new 构造函数调用 → this 指向新创建的实例
const p = new Person('xhj');
// this → 新对象 p { name: 'xhj' }
```

### 对比表

| 调用方式 | this 指向 | 示例 |
|---------|----------|------|
| `fn()` | 全局对象（window） | `Person('xhj')` |
| `new fn()` | 新创建的实例对象 | `new Person('xhj')` |

### 为什么 this 这么重要？

`this` 决定了**属性挂在谁身上**：

```javascript
function MyQueue() {
    this.stack1 = [];   // this 是谁，stack1 就挂谁身上
}

// 普通调用：stack1 挂到了 window 上（污染全局！）
MyQueue();
console.log(window.stack1);  // []

// new 调用：stack1 挂到了新实例上
const q = new MyQueue();
console.log(q.stack1);       // []
```

---

## 三、new 的四步过程

```javascript
const queue = new MyQueue();
```

`new` 背后做了四件事：

```
Step 1: 创建一个空对象 {}
Step 2: this 指向这个新对象
Step 3: 执行构造函数体（给 this 添加属性）
        → this.stack1 = []
        → this.stack2 = []
Step 4: 新对象的 __proto__ 指向 MyQueue.prototype
        → 实例获得原型上的所有方法
```

### 代码验证

```javascript
function MyQueue() {
    this.stack1 = [];
    this.stack2 = [];
    console.log(this);   // MyQueue { stack1: [], stack2: [] }
}

const queue = new MyQueue();

console.log(queue.stack1);  // []
console.log(queue.stack2);  // []
```

### 手动模拟 new

```javascript
function myNew(Constructor, ...args) {
    // Step 1: 创建空对象
    const obj = {};
    // Step 2: this 指向新对象（用 call 绑定）
    Constructor.call(obj, ...args);
    // Step 4: 连接原型
    obj.__proto__ = Constructor.prototype;
    // 返回对象
    return obj;
}

const queue = myNew(MyQueue);
```

## 四、原型式的面向对象

JS 的面向对象是**基于原型**的：

```javascript
// 构造函数：定义实例自己的属性
function MyQueue() {
    this.stackIn = [];
    this.stackOut = [];
}

// 原型对象：定义所有实例共享的方法
MyQueue.prototype.push = function(x) {
    this.stackIn.push(x);
}

MyQueue.prototype.pop = function() {
    if (this.stackOut.length === 0) {
        while (this.stackIn.length > 0) {
            this.stackOut.push(this.stackIn.pop());
        }
    }
    return this.stackOut.pop();
}

// 创建实例
const queue = new MyQueue();
queue.push(1);
queue.push(2);
console.log(queue.pop());  // 1
```

### 为什么方法放在原型上？

```javascript
// ❌ 放在构造函数里：每个实例都复制一份，浪费内存
function MyQueue() {
    this.stackIn = [];
    this.push = function(x) {   // 每次new都创建新函数
        this.stackIn.push(x);
    }
}

// ✅ 放在原型上：所有实例共享同一份
function MyQueue() {
    this.stackIn = [];
}
MyQueue.prototype.push = function(x) {   // 只创建一次
    this.stackIn.push(x);
}
```

---

## 五、用"人"来理解

| JS 概念 | 比喻 | 说明 |
|---------|------|------|
| 构造函数 `MyQueue` | "人"这个概念 | 抽象模板，定义有什么 |
| 实例 `queue` | 具体的人 "xhj" | 真实存在的对象 |
| `MyQueue.prototype` | xhj 的祖先 | 提供共享能力 |

- **构造函数**是图纸，定义实例有什么属性
- **原型对象**是公共技能库，所有实例共享
- **实例**是按图纸造出来的真实对象

---

## 总结

| 要点 | 说明 |
|------|------|
| JS 没有类 | 函数本身就是一等对象，可以当构造函数 |
| this 的关键 | 普通调用→window，new调用→新实例 |
| new 做了什么 | 创建对象→绑定this→执行代码→连接原型 |
| 方法放原型上 | 所有实例共享，节省内存 |

一句话：**JS 不需要 class，函数 + new + prototype 就是面向对象。**
