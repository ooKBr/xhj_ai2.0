# 一张图搞懂 JS 原型链：构造函数、实例、原型对象

> 理解了原型链，就理解了 JS 的灵魂。

## 前言

JS 的面向对象看似简单，实则是基于**原型链**的独特设计。很多人被 `prototype`、`__proto__`、`constructor` 绕晕。本文用一张图 + 几段代码，彻底讲透。

---

## 一、三者关系图

```
         prototype
构造函数 ──────────────► 原型对象
 MyQueue ◄──────────── MyQueue.prototype
         constructor          │
            │                 │
            │ new             ▲
            ▼                 │ __proto__
          实例 ───────────────┘
         queue
```

### 三条核心连接

| 从 | 到 | 属性 | 说明 |
|----|-----|------|------|
| 构造函数 | 原型对象 | `prototype` | 函数身上的属性，指向原型 |
| 原型对象 | 构造函数 | `constructor` | 原型身上的属性，指回函数 |
| 实例 | 原型对象 | `__proto__` | 实例身上的私有属性，指向原型 |

---

## 二、代码验证

```javascript
function MyQueue() {
    this.stack1 = [];
}

MyQueue.prototype.push = function(x) {
    this.stack1.push(x);
}

const queue = new MyQueue();
```

### 闭环验证

```javascript
// 1. 构造函数 → 原型对象
console.log(MyQueue.prototype);              // { push: ƒ }

// 2. 原型对象 → 构造函数
console.log(MyQueue.prototype.constructor === MyQueue);  // true

// 3. 实例 → 原型对象
console.log(queue.__proto__ === MyQueue.prototype);      // true

// 4. 三者闭环
console.log(queue.__proto__.constructor === MyQueue);    // true
```

---

## 三、原型链查找过程

### 实例先找自己，再找原型

```javascript
const queue = new MyQueue();
queue.push(1);   // queue 自己没有 push，去原型上找
```

查找流程：

```
queue.push(1)
    ↓
queue 自己有 push 吗？              ❌ 没有
    ↓ 沿 __proto__ 往上找
MyQueue.prototype 有 push 吗？      ✅ 找到了！
    ↓
执行 MyQueue.prototype.push()
```

---

## 四、实战：toString 去哪了？

```javascript
const wxf = new MyQueue();
console.log(wxf.toString());   // [object Object]
```

`wxf` 自己没有 `toString`，`MyQueue.prototype` 也没有，为什么不报错？

```
wxf.toString()
    ↓
wxf 自己有吗？                         ❌
    ↓ 沿 __proto__ 查找
MyQueue.prototype 有吗？               ❌
    ↓ 继续往上
Object.prototype 有吗？                ✅ 找到了！
    ↓
执行 Object.prototype.toString()
```

**这就是原型链：沿着 `__proto__` 一路往上找，直到找到为止。**

## 五、原型链的终点

```
queue
  └── __proto__ → MyQueue.prototype
                    └── __proto__ → Object.prototype
                                    └── __proto__ → null  ← 终点！
```

### 验证

```javascript
console.log(MyQueue.prototype.__proto__ === Object.prototype);  // true
console.log(Object.prototype.__proto__);                         // null
```

---

## 六、JS 设计哲学：一切皆对象

### 6.1 Object 是顶层对象

```
let obj = {}          // 本质就是 new Object()

Object()              // 是一个函数对象
Object.prototype      // 是一个原型对象

Function、Array、Date、RegExp   // 都是函数对象
```

所有对象的原型链，最终都会走到 `Object.prototype`，然后是 `null`。

### 6.2 任何对象的原型链终点都是 Object.prototype

```
数组：  []..__proto__ → Array.prototype → Object.prototype → null
函数：  fn.__proto__ → Function.prototype → Object.prototype → null
普通：  {}.__proto__ → Object.prototype → null
自定义：queue.__proto__ → MyQueue.prototype → Object.prototype → null
```

---

## 七、五条铁律

```
① 任何实例对象都有 __proto__，指向原型对象
② 任何函数都有 prototype，指向原型对象
③ 原型对象上有 constructor，指向构造函数
④ 实例先在自身找属性，找不到沿 __proto__ 往上找
⑤ 原型链的终点是 null
```

---

## 八、__proto__ vs prototype 区别

| 属性 | 谁身上的 | 指向谁 | 作用 |
|------|---------|--------|------|
| `prototype` | **函数** | 原型对象 | 给实例提供共享方法 |
| `__proto__` | **所有对象** | 自己的原型 | 原型链查找的通道 |
| `constructor` | **原型对象** | 构造函数 | 指回创建自己的函数 |

```javascript
// 函数既有 prototype 又有 __proto__
function fn() {}
fn.prototype       // → 原型对象（给实例用）
fn.__proto__       // → Function.prototype（函数自己的原型）

// 实例只有 __proto__，没有 prototype
const obj = new fn();
obj.__proto__      // → fn.prototype
obj.prototype      // undefined
```

---

## 总结

### 一句话记忆

> 构造函数的 `prototype` 指向原型对象，原型的 `constructor` 指回构造函数，实例的 `__proto__` 指向原型对象，三者形成闭环，实例找不到的属性就沿着 `__proto__` 一路往上找，直到 `null`。

### 知识图谱

```
原型链
├── 三者关系
│   ├── prototype（函数→原型）
│   ├── __proto__（实例→原型）
│   └── constructor（原型→函数）
├── 查找规则
│   ├── 先找自身
│   ├── 再沿 __proto__ 往上
│   └── 终点 null
├── Object 顶层
│   ├── 一切皆对象
│   └── 终点前一定是 Object.prototype
└── 设计哲学
    ├── 没有类，只有对象
    ├── 对象通过 __proto__ 连接
    └── 共享方法放原型上
```
